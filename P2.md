# Prompt 2 — MVP1 SpruceX Architecture

You are a Principal Azure Enterprise Architect.

Generate or update the **MVP1 PLANNED** askAlpha architecture. Start from the verified current application boundary; do not redesign React or FastAPI as separate deployed services.

## Preserve from current

- one Azure App Service package containing React static build output and FastAPI/Uvicorn;
- same-origin HTTPS JSON REST and SSE;
- browser/MSAL token acquisition from Entra;
- browser bearer token to FastAPI;
- FastAPI JWT validation using Entra JWKS;
- primary/fallback orchestration;
- direct Azure OpenAI access unless an approved gateway is explicitly implemented;
- conditional Azure AI Search metadata grounding;
- Azure SQL current analytics/control responsibilities;
- Managed Identity/approved workload identity.

## Add as planned MVP1 components/capabilities

- SpruceX access/network/firewall/DAC boundary;
- Azure Databricks SQL Warehouse;
- ADLS Gen2 governed data products;
- approved App Service-to-Databricks identity;
- source-qualified authorization;
- minimum durable user/query/data/export audit;
- golden and unseen-question evaluation;
- trusted baseline report/source-query reconciliation;
- hallucination/error thresholds;
- bounded reviewer iterations/time/tokens/cost;
- hardened visualization sandbox where code execution is enabled.

## Explicitly outside MVP1

- cross-source joins;
- required Redis runtime cache;
- Event Hubs/durable-outbox enterprise telemetry pipeline;
- formal showback/chargeback;
- Power BI replacement;
- any target component without approval.

- Use a left-to-right Mermaid flowchart.

- Show planned controls as in-process capabilities unless a deployable service is explicitly approved.
- Correct the Entra/browser/API arrow direction.
- Include dependencies, assumptions, exclusions, and MVP1 exit evidence.
